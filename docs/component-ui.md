# Component: UI Components

**Location:** `src/components/`, `src/components/multiplayer/`

All React components use the `"use client"` directive (the entire app is client-rendered; `page.tsx` uses `dynamic(..., { ssr: false })` to avoid hydration mismatches from `localStorage`-backed state).

---

## Component tree (local game)

```
layout.tsx
```

## ChessGame (`ChessGame.tsx`)

Root layout for the local game. Composes the header (title + AuthButton), the board + controls side-by-side, and the two headless components. Contains no game logic itself.

When `NEXT_PUBLIC_MULTIPLAYER=true`, the subtitle includes a "Play online" link to `/lobby`.

---

## BoardPanel (`BoardPanel.tsx`)

Handles all board interaction for local games. Reads from `useGameStore` and `usePreferences`.

**State managed locally (within the component):**

| State | Purpose |
|---|---|
| `selected` | Currently selected square (for click-to-move) |
| `dropSel` | Currently selected pocket piece type (Crazyhouse drop mode) |
| `pending` | Stores `{from, to, color}` when a move requires a promotion choice |

**Interaction flows:**

- **Drag and drop:** `onPieceDrop` calls `attemptMove(from, to)`. If the move is a promotion, sets `pending` and shows `PromotionDialog`. Otherwise calls `tryMove`.
- **Click to move:** First click on a piece sets `selected` and shows legal-move dots. Second click on a target square calls `attemptMove`. Clicking the same square deselects.
- **Drop mode (Crazyhouse):** Clicking a pocket piece in `PocketBar` calls `selectDrop`, setting `dropSel`. Legal drop squares are highlighted in green. Clicking a highlighted square calls `tryDrop`.
- **Promotion:** `PromotionDialog` appears as an overlay. On choice, `tryMove(from, to, pieceType)` is called. On cancel, `pending` is cleared.

**Square highlights:**

- Selected piece square: yellow background
- Legal move targets: dark radial-gradient dot
- Legal drop targets: green radial-gradient dot

**Lock conditions:** The board is non-interactive (`locked = true`) when:
- The game has ended (`result` is set)
- The AI is thinking (`thinking` is true)
- It is a computer-controlled side's turn

Selections are cleared on every state change (via `useEffect` on `state`).

## PocketBar (`PocketBar.tsx`)

Displayed above and below the board in Crazyhouse. Shows pieces held in hand for one colour, sorted by value (Q, R, B, N, P).

**Props:**
- `color` — which side's pocket
- `pieces` — array of `PieceType` (may contain duplicates; a count badge shows for 2+)
- `active` — whether this side can make a move (controls interactivity)
- `selected` — the currently selected piece type for drop mode (highlights that button)
- `onSelect(type)` — called when a pocket piece is clicked

An empty pocket shows "Pocket empty" in muted text. Piece buttons are disabled when `active` is false.

---

## PromotionDialog (`PromotionDialog.tsx`)

An overlay that appears on top of the board when a pawn reaches the back rank. Shows Q, R, B, N buttons using `PieceGlyph`. Clicking outside (or the cancel button) dismisses it without applying the move.

**Props:** `color`, `onChoose(type)`, `onCancel()`

---

## ControlsPanel (`ControlsPanel.tsx`)

The right-hand side panel. Contains four collapsible sections:

### Variant selector
Dropdown above the Opponents section. Selects the rule set and starts a new game immediately.

### Opponents
Radio buttons for White and Black (Human / Computer). Difficulty radio group (Easy / Medium / Hard). Changes take effect immediately via `usePreferences`.

### Captured
Delegates to `CapturedPanel`. Shows material advantage.

### Moves
Scrollable move log in algebraic notation. Notation is generated by `describeMove()` in `gameStore.ts`.

**Status bar** above the buttons shows the current game state: whose turn it is, how many moves remain (for Monster King), "Computer is thinking…", or the game result.

**Action buttons:** New game, Undo, Flip (swaps board orientation).

---

## CapturedPanel (`CapturedPanel.tsx`)

Reads `moves` and `history` from `useGameStore` and derives captured pieces via `deriveCaptured()`. Displays each side's captures as a row of glyphs with a material advantage score (positive = White is ahead).

---

## Collapsible (`Collapsible.tsx`)

A generic accordion wrapper with a chevron icon. Opens by default (`defaultOpen={true}`). Used by `ControlsPanel` to contain the four sections.

---

## PieceGlyph (`PieceGlyph.tsx`)

Renders a Unicode chess glyph (♚, ♛, etc.) as a styled span. Used by `CapturedPanel` and `PocketBar`.

**Props:** `color`, `type`, `size?` (font size in px, defaults to 18)

---

## AuthButton (`AuthButton.tsx`)

Shows sign-in buttons (one per configured provider) when signed out, or the user's avatar/name and a sign-out button when signed in. Fetches the available providers from `getProviders()` on mount so the button list updates automatically when providers are configured.

---

## PreferenceSync (`PreferenceSync.tsx`)

Headless component (renders `null`). Manages the two-way sync between `localStorage` and the database:

1. **On sign-in:** Calls `GET /api/preferences`. If a row exists, overwrites the local Zustand state with the DB values. If no row exists, calls `PUT /api/preferences` to seed from the current local values.
2. **On preference change while signed in:** Waits 600ms (debounce), then calls `PUT /api/preferences`.
3. **On sign-out:** Stops syncing; local `localStorage` values continue to apply.

## Providers (`Providers.tsx`)

Root layout wrapper that renders:
1. **Banner** — sticky `<Image>` (`banner2.png`), 56px on mobile / 100px on desktop.
2. **Nav** — see below.
3. **Page content** — `{children}` in a scrollable flex container with bottom padding on mobile (leaves room for the fixed bottom nav bar).
4. **PreferenceSync** — headless, placed here (not inside `ChessGame`) so settings-page changes are not overwritten when navigating back to the home page.

Wraps everything in `<SessionProvider>` from `next-auth/react`, which makes the session available to all client components via `useSession()`.

---

## Nav (`Nav.tsx`)

Dual navigation: a **desktop sidebar** (hidden on mobile, `w-48`, sticky below banner) and a **mobile bottom bar** (fixed, `h-14`, hidden on desktop). Both render the same links: Home, About, Settings, and Play Online (when multiplayer is enabled). The `AuthButton` appears at the bottom of the sidebar on desktop and inline in the bottom bar on mobile.

An **Admin** link additionally appears in the desktop sidebar only (not the mobile bar) when the signed-in user's email matches the hardcoded admin email (checked via `useSession()`). This is a UI convenience only — the real access control is on the `/admin` page itself.

---

## Settings page (`src/app/settings/page.tsx`)

A dedicated `/settings` route for cosmetic preferences. Contains:
- **Board skin** — selects from `BOARD_THEMES`
- **Piece skin** — selects from `PIECE_SETS`

Changes are persisted via `usePreferences` (localStorage, or DB if signed in).

## About page (`src/app/about/page.tsx`)

Static page describing the project, the author, variants, features, and tech stack.

---

## Admin page (`src/app/admin/page.tsx`)

A **server component** (no `"use client"`) that shows the top 100 rows of each database table: `User`, `Account`, `Session`, `Preferences`.

**Access control:** the page calls `auth()` server-side and compares `session.user.email` against a hardcoded admin email. Any other visitor (signed in or not) is redirected to `/` before any data is fetched. Because the check runs on the server, the data never reaches an unauthorised browser.

**Rendering:** the four tables are fetched in parallel with `Promise.all` + `prisma.<model>.findMany({ take: 100 })` and rendered as horizontally scrollable tables with truncated cells. Dates are formatted server-side; no client JS is involved.

See [component-auth.md](./component-auth.md#admin-page-authorisation) for the authorisation pattern.

## Responsive layout

The app is fully responsive:
- **Mobile:** compact 56px banner, no sidebar, board scales to `min(100vw − 2rem, 100vh − 200px, 460px)`, controls stack below the board, fixed bottom nav bar.
- **Desktop:** 100px banner, 192px sidebar, board + controls side-by-side, no-scroll layout (`h-[calc(100vh−100px)]`).

The `BoardPanel` container uses CSS `min()` with three values to handle both cases with a single rule.

## Theming

**Board themes** (`src/theme/boardThemes.ts`): Five themes, each a `{ id, name, light, dark }` pair of CSS colour strings. Applied via `darkSquareStyle` / `lightSquareStyle` on the `Chessboard` component.

**Piece sets** (`src/theme/pieceSets.tsx`): Three sets:
- `"default"` — react-chessboard's built-in SVG pieces (no custom rendering)
- `"glyph"` — Unicode chess glyphs (♔♕♖…) in an SVG `viewBox` with stroke for contrast on both square colours; U+FE0E variation selector forces monochrome rendering
- `"minecraft"` — pixel-art SVG pieces via a `pixelPiece()` helper with `imageRendering: pixelated`

New image-based sets (e.g. cburnett, alpha) can be added by adding an entry to `PIECE_SETS` that returns a `PieceRenderObject` (a record of React components keyed by `"wP"`, `"bK"`, etc.).
